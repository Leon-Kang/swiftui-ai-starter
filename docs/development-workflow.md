# Development Workflow

## 日常开发流程

1. 先运行 `scripts/init-project-skills.sh` 检查技能状态；需要安装缺失的 required curated skills 时再显式添加 `--install`
2. 再读 `AGENTS.md`
3. 查共享组件登记区和 `docs/component-registry.md`
4. 判断需求属于：
   - Feature 私有能力
   - 共享 UI
   - 共享 Core 能力
   - 共享 AI 能力
5. 能扩展现有共享能力就不新建
6. 必须新建时，遵守单文件单主类型
7. 新增共享组件或共享能力后，立即更新登记文档
8. 运行约定检查脚本和测试
9. 若补了新规则，同步补脚本或 CI，禁止只改文档不改执行层

## 什么时候该扩展已有组件

满足任一条件就优先扩展：

- 新需求和已有组件职责相同，只是多一个状态或样式
- 新需求只是在已有组件基础上新增参数
- 两个页面已经出现近似 UI
- 功能差异只在文案、图标、回调或样式级别

## 什么时候允许新建共享组件

必须同时满足：

- 职责明显不同于现有组件
- 不会和现有组件形成“第二套主按钮 / 第二套卡片 / 第二套空状态”
- 至少有两个未来可复用场景
- 输入输出可以稳定定义

## 新共享组件的完成定义

创建后必须全部完成：

- 文件放在共享层正确位置
- 遵守单文件单主类型
- 提供 Preview 或示例用法
- 补最小测试或测试策略说明
- 更新 `AGENTS.md`
- 更新 `docs/component-registry.md`

## 代码评审关注点

- 是否绕过了共享层
- 是否重复造轮子
- 是否把页面私有实现错误地提升为共享能力
- 是否违反单文件单主类型
- 是否新增组件但未登记
- 是否新增了用户可见硬编码文案
- 是否把 UI 更新留在非 `@MainActor` 上
- 是否新增了文档规则但没有对应校验
